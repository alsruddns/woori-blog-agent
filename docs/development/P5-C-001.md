## Changes

- Added `scripts/status.ps1`, `start.ps1`, `stop.ps1`, `restart.ps1`, and shared process inspection. Managed API/Dashboard start checks refuse occupied ports, track only a verified project runner, and probe a GET-only route. Stop checks executable, checkout, PID start time, port owner and established TCP sessions; it requests normal window close only for a process launched by this manager. Unmanaged listeners are refused. It never force-kills or removes a live PID record.
- Added local AI status/start selection and a best-effort graceful Ctrl+Break helper for a process started with a verified project process group. The existing model process was not restarted or signalled.
- Application DB connections under pytest now verify database `woori_blog_agent`, login `woori_app`, and a loopback server address, then run within a forced-rollback transaction. Existing direct migration tests continue to use a disposable schema inside an outer rollback. No dedicated test login was provisioned; this remains a follow-up if the project moves away from its documented rollback boundary.
- Confirmed the 12 Phase 5-B rows were the four identified immutable integration-test fixture batches. They were neither changed nor deleted. The manuscript workbench reads article drafts from the isolated evaluation DB; it does not source the operations `content_versions` fixture rows, so no title-based filtering or reclassification was added.
- Added migration 033, `/admin/research/publication-approvals`, and UI controls for approval/revocation. An approval is bound to the current immutable editorial version and exact body hash, requires that version to pass machine checks and the latest human editorial decision for the same version to be `approved`, and appends a new audit event. Edits require a new approval. Approval creates no job, does not set `publish_ready`, and does not unlock Blogger writes.
