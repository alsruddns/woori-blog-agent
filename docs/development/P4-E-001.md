# P4-E-001 — 운영 준비 차단 원인 분석

## 작업 기록

- 작업 ID: P4-E-001
- 작업 일시: 2026-10-27 (Asia/Seoul)
- 변경 사유: 영어 평가 quota가 SEC의 다른 언어 평가까지 막는 것처럼 표시되고, 평가 순서와 원본 초안 의존성이 혼재되어 있었다. Blogger의 비용·Cloud 결제 상태가 확인되지 않아 읽기 호출이 차단되어 있었다.
- 기존 상태: en 평가 quota 2/2, ko·ja·zh-CN 각 1/2. Fed 기계 검사 통과 원고 4개, 사람 검토 0개. Blogger API 비용 및 Cloud 프로젝트 결제 연결 미확인.
- 목적: 언어별 quota와 실제 생성 선행 조건을 분리해 표시하고, 실패가 quota를 불필요하게 소비하지 않도록 한다. 비용이 검증되지 않은 Blogger API와 공개 피드 요청은 차단한다.
- 변경 전: 비영어 SEC 작업은 성공한 동일 주제 영어 원고가 없으면 Worker 실행 후 `source_version_missing`으로 실패했다. 운영 준비 UI는 영어 quota만 보고 SEC 전체가 quota로 막힌 것으로 표시했다. 과거 Mock 성공은 현재 검증처럼 보일 수 있었다.
- 변경 후: SEC 상태에 언어별 잔여 quota와 동일 주제의 성공한 영어 원본 초안 필요 여부를 표시한다. 비영어 SEC 작업은 해당 원본이 없는 경우 enqueue 전에 중단한다. 저장된 결과가 없는 실패 시도도 대시보드에 나타나며 사람 검토 대기 원고로 집계하지 않는다. Mock Publisher와 Worker 검증은 `verified_historical`로 표시한다.
- DB 변경: 신규 마이그레이션 없음. 운영 DB schema 28, 평가 DB schema 26을 읽기 전용으로 확인했다. 양쪽 `audit_events` 변경 차단 트리거가 활성화되어 있다.

## SEC 평가 및 차단 원인

영어 quota는 한국시간 기준 2026-10-28 00:00에 초기화된다. 영어 quota가 다른 언어의 quota를 공유하지는 않는다. 다만 현재 파이프라인은 현지화 원고를 만들 때 같은 SEC 주제의 성공한 영어 source draft를 실제로 요구한다. 그러므로 영어 원본이 없으면 타 언어 실행은 quota가 남아도 준비되지 않는다. 이는 단순한 우선순위가 아니라 데이터 선행 조건이다.

평가용 DB `woori_blog_agent_eval`에서 ko SEC 실행 1건을 실제 Worker로 시도했다. 실행 ID `b8635e8c-8999-4c08-8a15-e01f0290b61e`는 `source_version_missing`으로 실패했고, 평가 산출물은 없었다. 이 시도는 기존 정책대로 ko quota를 1/2에서 2/2로 소비했다. quota 초기화나 재시도는 하지 않았다. 모델 프로세스와 Qwen3-4B Q4_K_M Vulkan 런타임은 실행했지만 실패가 추론 전에 발생해 모델 호출 0회, 생성 토큰 0개였다. 측정된 작업 시간은 2.43초, worker RSS 관측값은 약 54.4 MiB, GPU 이용률은 미측정이다. 실행 전/후 가용 RAM은 각각 약 9.91 GiB/9.90 GiB, CPU 샘플은 26.7%/32.5%, 디스크 여유는 약 202.9 GB였다. 실패 후 프로젝트 전용 모델 프로세스를 PID와 실행 경로 확인 후 정상 종료했다.

현재 quota는 en 2/2, ko 2/2, ja 1/2, zh-CN 1/2이다. ja와 zh-CN은 각각 quota가 남아 있지만 같은 SEC 주제의 성공한 영어 원본 초안이 없어 차단 상태다. en quota가 다시 허용될 때 성공한 영어 원본을 먼저 생성해야 이후 언어 평가가 가능하다. 영어 원고의 실제 생성·기계 품질 검증은 이번 단계에서 완료되지 않았다.

## Blogger 비용과 읽기 경로

Google의 Blogger API 문서는 인증 방식과 GET/쓰기 메서드를 설명하지만, 이번에 확인한 공식 자료에는 Blogger API의 요청당 가격이나 명시적인 무료 quota가 없다. Cloud API quota는 요청량 제어이며 프로젝트 지출 한도와 같지 않다. Cloud 결제 문서는 프로젝트 사용 비용이 연결된 활성 Billing account로 청구됨을 설명하지만, 현재 로컬 Blogger readonly OAuth 권한으로 이 프로젝트의 Billing account 연결 상태나 다른 과금 서비스 설정을 조회할 수 없다.

Google은 공개 Blogger Atom/RSS feed와 익명 접근 가능성을 문서화한다. 그러나 이번 검토 자료만으로 자동 재사용 권리, 요청 한도, 추가 비용 0원을 확정할 수 없어 대체 피드도 allowlist에 추가하지 않았고 요청하지 않았다. 이번 단계에서 Blogger OAuth GET, 공개 feed GET, Blogger 쓰기는 모두 0회다. `google_blogger_read`의 `provider_cost_unverified` 및 `calls_allowed=false` 상태를 유지한다.

근거: [Blogger API usage](https://developers.google.com/blogger/docs/3.0/using), [Blogger API getting started](https://developers.google.com/blogger/docs/3.0/getting_started), [Google API quota caps](https://docs.cloud.google.com/apis/docs/capping-api-usage), [Verify Cloud Billing status](https://docs.cloud.google.com/billing/docs/how-to/verify-billing-enabled), [Cloud Billing project behavior](https://docs.cloud.google.com/billing/docs/how-to/modify-project), [Blogger feed protocol](https://developers.google.com/blogger/docs/2.0/developers_guide_protocol), [Blogger feed help](https://support.google.com/blogger/answer/97933?hl=en). 확인 일시: 2026-10-27.

## Fed 사람 검토 및 운영 준비

현재 격리 평가 DB에 Federal Reserve 기계 검사 통과 원고 4개가 있다. 운영 DB의 사람 검토 이력은 0개이며 4개 모두 `pending`이다. `/research` 화면은 전체 원고, 문단·문장 출처 표식, 출처 원문 및 사실, 날짜·숫자·고유명사, 언어별 제목·키워드, 검토 의견·수정 요청, append-only 검토 이력을 제공한다. 편집 품질 승인에는 사실 정확성·번역 자연스러움·독자 가치의 긍정 검토가 필요하고, 이는 Blogger 발행 권한과 분리되어 있다. 이번 작업에서는 실제 사람 검토나 승인을 기록하지 않았다.

운영 준비 화면은 현재 DB quota, 사람 검토, Blogger 비용 차단, 실제 Blogger 읽기 미검증, Mock Publisher 과거 실행, Worker 과거 복구 검증, 운영 쓰기 차단 및 별도 발행 승인 상태를 표시한다. 과거 Mock/Worker 결과에는 시각과 historical 범위를 표시한다. 현재 운영 DB 기준 Blogger 쓰기 작업 0, publishing record 0, 비-Mock 발행 작업 0, `publish_ready` 평가 0, 자동 발행 정책 0이다.

## 미완료 및 위험

- SEC 영어 quota가 소진됐고 해당 SEC seed의 성공한 영어 원본 초안이 없다. 이번 한국어 시도도 생성 전에 실패했다. 남은 ja·zh-CN quota를 사용하지 않았다.
- Fed 4개 언어 원고 사람 검토 0/4.
- Blogger API의 요청 비용/free quota, Cloud Billing account 연결, 프로젝트의 다른 과금 서비스는 확인되지 않았다. Blogger API와 public feed 모두 live GET 보류.
- Google Cloud Console의 billing association은 사용자가 읽기 권한으로 별도 확인해야 한다. 비용이 명시적으로 0원이라고 증명되기 전까지 Blogger provider를 unblock하지 않는다.
- 운영 Blogger 발행 및 `publish_ready`는 비활성 상태를 유지한다.
- 조사 중 `.env.evaluation-migration`의 한 줄이 터미널 도구 출력에 노출되었다. 값은 재인용·복사·커밋하지 않았고 데이터베이스 변경도 수행하지 않았다. 해당 evaluation DB owner credential을 교체하고 로컬 ignored 파일을 갱신하는 조치가 필요하다. 서비스 중단을 피하려고 자동 회전은 하지 않았다.
