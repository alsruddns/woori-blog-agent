These are point-in-time idle diagnostics, not inference measurements.

The existing `.local/runtime.json` matched PID 39500 but lacked the checkout identity, process creation time, exact launch-argument signature, model checksum, batch-thread value, executable identity fields, and managed process-group marker now required by the stop script. The parent process was no longer present. `scripts/stop-local-ai.py` was run and exited 2 with an identity-verification refusal; it did not signal PID 39500 or rewrite the runtime record. A follow-up confirmed the process and listener still existed and the metadata remained unchanged. This fail-closed refusal is intentional; do not reconstruct trust metadata for a process after launch.

## Implementation

- Added `scripts/local_ai_process.py` to validate project root, exact local executable, PID creation time, model checksum, CPU/batch/GPU/host/port/context/parallel options, API-key-file location, and managed process-group metadata. Command signatures omit the API-key-file argument and value; credentials are never printed or persisted in the signature.
- New launches record the metadata needed for later exact identity checks. The stop path now verifies listener ownership, refuses active client connections, and requests only graceful process-group shutdown. It never force-kills an unverifiable process.
- Added a per-inference monitor that records system CPU separately from llama process CPU normalized against total logical CPU capacity, RSS peak, sample count, and the unchanged 80% limit. At `>=80%`, a sampling failure, or monitor termination, it closes the active HTTP transport and raises a non-retryable failure. Partial streaming text is not returned as a `Draft`; failure resource metrics are included in the job audit event. GPU utilization during the monitored request is reported as unmeasured (`null`), not guessed.
- The existing idle-process preflight and thread policy remain in force. The monitor does not disable or relax them.
