# P5-CODEX-162 Trends authoring and startup defaults

- **Work ID:** P5-CODEX-162
- **Work time:** 2026-11-18, Asia/Seoul
- **Reason:** The operator requested reliable Trends automatic publication, consistent manual/automatic worker mode after service startup, and persistent publication operation.
- **Existing problem:** Publication controls were already enabled at revision 29 and the Publication Worker was healthy in `scheduled-auto-manual-trends` mode, but recent Trends authoring attempts failed strict body validation with `trend_factual_paragraph_citation_required`. The Windows logon task invokes `start-services.ps1` without an explicit publication mode, whose old default was only `manual-confirmed`; the single-service startup entry points defaulted to `mock-only`.
- **Purpose:** Make future Trends manuscripts meet the existing citation contract more consistently and make normal service start paths choose the same Trends-capable execution mode, while retaining database policy, per-blog/language scopes, revision acknowledgments, and all quality, rights, duplicate, interval, emergency-stop, and write gates.
- **Before:** Trend prompt only said factual paragraphs must have citations; startup defaults differed across all-service and single-service launchers. Runtime controls revision 29 were already ON for manual, master Auto, Trends Auto, Scheduled Auto, and operator approval; 10-minute global interval; the Publication Worker and Research Worker heartbeats were fresh.
- **After:** Prompt now spells out paragraph-by-paragraph citation requirements, including an eight-word minimum aligned with validation, and tells the author to remove unsupported paragraphs or return `insufficient_evidence` rather than invent citations. `start-services.ps1`, `start.ps1`, and `start-publication-worker.ps1` default to `scheduled-auto-manual-trends`; explicit mode arguments remain honored. Startup does not mutate persisted controls or create new policy events. The existing login task still targets `start-services.ps1`, so its no-argument launch uses the updated default. Existing historical failed authoring jobs remain held and are not retried or reauthorized.
