# P3-7-001 — Evidence-backed staged generation

- **Work ID:** P3-7-001
- **Date:** 2026-10-26 (Asia/Seoul)
- **Reason:** Phase 3.6 reported 17 generated samples, all `quality_held`, with missing evidence markers, unsupported values/names, repetition, language drift, and output failures. Increasing model size alone does not establish factual or linguistic quality.
- **Existing problem:** Generation steps were not independently durable or inspectable, and retry evidence could not be reviewed stage by stage. Model metrics were also lost when validated model output was converted to a Pydantic object.
- **Objective:** Persist source-to-draft stage inputs/outputs and evidence links, bound retries, detect unsupported surface-level facts, expose the records in `/research`, and compare the same reviewed source across active languages without approving quality or publication.
- **Before:** The Phase 3.6 17-sample batch used the earlier generation flow and every sample was held. It had no per-attempt stage relation.
- **After:** Migration 014 stores immutable terminal stage attempts; the worker records source collection, fact extraction/validation, bounded outline, per-section generation/localization, claim verification, SEO and persistence. It saved four actual Qwen3 4B Q4_K_M drafts from one reviewed Federal Reserve source across en/ko/ja/zh-CN. All four remain `quality_held`, `seo_audits.passed=false`, and `publish_ready=false`.
- **Model/source:** Qwen3 4B Q4_K_M, pinned revision `bc640142c66e1fdd12af0bd68f40445458f3869b`, SHA-256 `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`, Apache-2.0; project-local llama.cpp b11889 Vulkan, RX 570 configured for 20 offloaded layers. No model was downloaded during this phase.

All four final target JSON objects parsed and were persisted. The deterministic final gate passed **0/4** drafts; no sample became publish-ready. The database reported uncited-paragraph checks passing, but the broader checks still found unsupported numbers and/or names, keyword/title problems, and Korean title/keyword language mismatch. Chinese and Japanese script checks passed, but that is not a fluency or semantic-translation approval. English claim verification and SEO were held as well. The run therefore demonstrates stage traceability and explicit failure retention, not content-quality success.

The Phase 3.6 baseline was 0/17 passing the final gate. The Phase 3.7 run was also 0/4. These are small and unequal samples over one Federal Reserve topic, so they do not show a quality improvement or represent all seven categories. The stage retry policy did recover some individual sections after the first attempt, but that did not improve final draft approval.

During the run, a Windows working-set spot sample reached about 6.62 GiB. This is an observed sample, not a guaranteed process peak. Per-language CPU percentage, per-language GPU utilization, completion token counts, and tokens/second were not preserved in this run because the section metric attribute was dropped while reconstructing the validated draft. The code now carries metrics alongside each staged output and a regression test verifies persistence; the new instrumentation has not yet been re-measured in another live four-language run. GPU use is therefore recorded only as the configured Vulkan backend/20 offloaded layers; utilization remains unavailable. No exact token throughput or per-language CPU/GPU values are claimed.

The live output exposed an important limitation: citations and matching surface names/numbers cannot establish semantic entailment. The deterministic gate rejects unsupported detected names/values and the final human-review state remains mandatory; it does not prove that paraphrased claims are semantically true. The section gate was tightened to reject detected names that do not occur in the assigned evidence, and a numbered Markdown heading regression was added. These final gate refinements passed unit tests but were not rerun against the live model in this work item.
