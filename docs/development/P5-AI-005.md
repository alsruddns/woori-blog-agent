## What the measurements establish

The P5-AI-004 article-generation request used the same model/runtime and had a measured system-wide CPU peak of 94.1% after 147.19 seconds. Its output was cancelled and no valid article was returned. That run did not retain per-process CPU samples, so the 94.1% peak cannot be attributed to llama.cpp alone. It is evidence that the complete long-running workload crossed the system ceiling under concurrent machine activity, not proof of one specific process as the cause.

Current server options were verified from the process command line and `.local/runtime.json`: llama.cpp b11889, Qwen3-4B-Q4_K_M (manifest SHA-256 `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`), Vulkan, `-t 4`, `-tb 4`, `-ngl 20`, `-np 1`, context 8192. The launcher sets batch threads equal to inference threads. Twenty GPU layers are requested; this does not establish that all computation is offloaded. The prior completed P5-AI-002 benchmark observed GPU-engine utilization, but P5-AI-004 and this probe did not sample GPU utilization during inference.

At idle, the llama process used 0% CPU in the sampled intervals. System CPU ranged from 1.7% to 21.5% over eight one-second intervals. Other active processes included Chrome, Codex UI, Windows/System and security-related processes. These are concurrent background load observations only; none can be identified as the cause of the earlier 94.1% peak.

## Bounded probe

Before sending a request, the local server identity was rechecked, available RAM was 10.89 GiB, free disk was 171.18 GiB, and one-second system CPU preflight was 9.6%. A single direct loopback chat request asked for a short fixed response with `max_tokens=8`; it did not write a draft, consume evaluation quota, call a paid provider, or contact Blogger. A separate monitor sampled system CPU every 0.25 seconds and closed the response if any sample reached 80%.

The request completed in 1.505 seconds with 25 prompt tokens and 3 completion tokens. Peak sampled system CPU was 49.0%; llama process CPU peaked at 31.7% of total machine capacity (the process reading is normalized across 12 logical processors). Process RSS peaked at 2,541 MiB. The 80% limit was not crossed and there was no retry. GPU utilization was not measured during this request. Its brevity makes token throughput unrepresentative and it does not validate long-form generation.

## Cause assessment and next settings

The confirmed cause is workload-level CPU saturation during the previous long generation while the global system was also doing work. The exact attribution is unresolved because P5-AI-004 did not capture per-process samples at the peak. The current configuration permits four inference threads and four batch/prompt-processing threads; Vulkan offloads a requested subset of layers, while the remaining work and runtime/driver activity can still consume CPU. The current short request stayed below the ceiling at these settings, but this is not evidence that a full article will.

`-t 2 -tb 2` is a reasonable bounded candidate for a future controlled test because it halves the configured CPU worker counts while retaining the same Vulkan backend and GPU-layer request. This is a hypothesis, not a measured improvement. `-t 2 -tb 1` could further limit prompt-processing concurrency but may increase prefill latency. Neither was applied or tested: the existing live server's incomplete management metadata prevents the project shutdown script from proving a safe graceful-control path. Starting a second Vulkan model process would add memory/GPU contention, so it was not attempted.

The inference provider records system CPU samples, but its normal cancellation check is tied to job state; `pipeline.resources_ok` checks CPU before starting work. It does not currently enforce the 80% CPU threshold as a live cancellation condition by itself. P5-AI-004's one-off evaluation monitor supplied that live stop. This is an operational limitation to resolve before treating 80% as an in-flight hard stop for unattended long generations; do not raise or bypass the ceiling.
