# P5-A-001 — Manuscript editing and publication preparation

- Date: 2026-10-27 (Asia/Seoul)
- Branch: `develop`; baseline commit `480aef08fc170e6a4564fa4154b72c11ebccd3e7`
- Implementation commit: `ecc80ae` (`Add : [Editorial] Build versioned manuscript editing workspace`); pushed successfully to `origin/develop`.
- Purpose: let editors correct source-backed drafts and keep each edit immutable without enabling Blogger writes.
- Before: Phase 4-M review workspace had source/evidence and append-only review, but lacked a complete formatted editor, versioned publishing metadata, remote-post identity binding, and a complete stored-draft list.
- Existing content policy: never rewrite evaluation originals, prior editorial versions, or audit rows. Editor changes are new rows. Tests of persistence ran in a transaction that rolls back.

## Changes

- Added an `/research` manuscript manager with dynamic locale/blog/category filters, editorial and publication-state filters, title search, modified-time sorting, full source/fact/quality details, review history, and original/revision comparison.
- Expanded editor fields for title, sanitized HTML, SEO description, keywords, Blogger labels, active locale-matched blog, publication intent, and a Korea-local planned time. Preview is isolated in a sandboxed iframe with a restrictive CSP and mobile/desktop sizing.
- Added server-side HTML allowlist sanitization. Script/style/active embeds, event handlers, and unsafe URLs are removed; approved formatting and source markers remain.
- Human review and publication approval stay separate. `manual` is the default. A planned time or mode is metadata only; it creates no publication job. `publish_ready` remains false and the live Blogger write adapter remains disabled.
- Published edits must point to an already recorded blog/post mapping. IDs are never generated or accepted without that mapping; a mapped edit remains associated with the existing post identity.
- Migrations 030–032 add versioned editing metadata, existing Blogger post ID binding, and a base-body hash. `migrate.py` and the isolated restore/worker schema checks now recognize version 32.
- The review API uses an advisory transaction lock for optimistic concurrency. It does not request row-update locks on append-only tables, preserving the app account's least privilege.
- The evaluation-draft listing retains the latest evaluation for every stored content-version ID. The live evaluation DB contained 18 distinct saved Fed/SEC versions (en 7, ko 4, ja 4, zh-CN 3); all 18 are returned rather than collapsing multiple versions by topic/language.
