## DB 및 보안
초기 4개 URL을 설정 데이터로 등록했으며 Google Blog ID는 모두 NULL이다. 주소 검증을 위한 외부 호출도 하지 않았다. 기존 전용 DB만 woori_owner로 마이그레이션했다. API/Worker는 woori_app을 계속 사용하며 .env.bootstrap/.env.migration을 읽지 않는다. 다른 프로젝트 DB·계정·파일은 변경하지 않았다.

002는 기존 콘텐츠 필드를 수정하지 않고 localization_id 메타데이터만 역채움한다. 불변 트리거를 같은 트랜잭션과 테이블 잠금 안에서 잠시 중단·복원했다. 기존 UUID·제목·본문·출처·시각·감사 이벤트를 보존하는 통합 테스트를 추가했다. 이미 적용한 SQL은 변경하지 않고 003/004 후속 마이그레이션으로 참조 제약 및 권한을 추가했다.

생성·번역·품질 지원 플래그만으로는 발행할 수 없다. 검증된 정확한 언어 지원 레지스트리는 현재 비어 있다. 일반 설정 API는 Blog ID, 연결/테스트 검증, 모델 검증, 자동 발행 허용 필드를 받지 않는다. DB CHECK와 기존 호출 차단이 자동 발행/AI 네트워크 접근을 계속 막는다. 설정 감사 payload는 원문 정책 대신 엔티티 참조·actor·변경 fingerprint를 기록한다. fingerprint는 정책 복원이나 외부 무결성 증명이 아니다.

## 검증 결과
- PostgreSQL 001 → 004 순차 마이그레이션 및 재실행 성공.
- pytest 30개: 기존 9개와 태그 검증·정규화, 인증, 언어 추가/중복/비활성화, 동일 언어 복수 블로그, 국가별 프로필, 스케줄·시간대, 용어집·카테고리, 설정 감사, 자동 발행 우회 차단, 기존 데이터 보존, 국가별 버전 독립성과 발행 기록 참조 보존 검증.
- Ruff, mypy, Next lint·타입 검사·production build 및 Python wheel 빌드 통과. 실제 HTTP로 대시보드/설정 렌더링, 동일 Origin 프록시 전달, 외부/누락 Origin 차단, HTML 토큰 비노출 확인.
- 마이그레이션 소유자 계정은 추가 테스트에서 임시 스키마/발행 이력의 롤백 트랜잭션에만 사용. 가짜 원격 게시 이력과 테스트 블로그는 영구 저장하지 않았다. 기존 진단 실행 테스트 이벤트는 보존한다.
- 전용 DB 마이그레이션 전 백업 및 archive list 검증 성공. 복원 리허설은 이번 범위에서 미실시.

## 발견한 문제와 해결
- 국가별 카테고리 등록 테스트에서 공통 categories INSERT 권한 누락 발견: 004에 최소 INSERT 권한 및 DB 감사 트리거 추가.
- BCP 47 음성 테스트의 not 태그가 실제 등록된 언어이며 뒤 부분은 확장 태그로 유효함을 확인: 잘못된 테스트 fixture를 실제 무효 태그로 교체.
- croniter 타입 선언 부재: types-croniter 개발 의존성 추가.
- Windows 기본 cp949 문서 읽기 오류: UTF-8 명시 후 복구. 테스트 SQL 문자열 escape 오류도 수정하고 재검증.
- 실제 Next 프록시에서 내부 URL의 Origin과 외부 요청 Host 차이로 정상 요청 403 발생: 루프백 Host 허용 목록과 정확한 Origin 일치 검사로 수정. 후속 편집 문법 오류까지 lint/build로 확인·수정.

## 남은 문제
- 실제 AI/번역/SEO/발행 Worker와 Search Console 수집기는 미구현이며 준비 상태는 미검증/차단이다. 스케줄은 저장만 한다.
- Blog ID는 향후 API 조회·연결 검증 후 저장해야 한다. custom Blogger 도메인은 현재 등록 대상에서 제외한다.
- hreflang은 Posts API 전용 필드가 없음을 공식 문서에서 확인했고 테마/head 검증이 남아 있다. 구현하지 않았다.
- 정책 감사는 fingerprint만 보관하므로 이전 정책 원문 복원 기능은 없다. 콘텐츠/발행/감사 기록은 별도로 불변 보존한다.
- 기존 httpx 테스트 클라이언트 사용 중단 예정 경고 1건 유지. 정기 백업/알림·복원 리허설·Task Scheduler 등록 및 재부팅 검증은 이전 잔여 과제.
- 모든 작업은 develop에서 수행한다. main 병합·배포·운영 Blogger 쓰기는 하지 않는다.
