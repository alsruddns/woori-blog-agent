# P5-CODEX-012 — 자동 원고 파이프라인 상태 진단

## 목표와 판정

2026-10-29 KST 기준으로 P5-CODEX-011의 실제 구현과 남은 의존성을 재검증하고, 4개국 장마감·주간 금융·Trends 자동 생산의 실행 가능 범위를 기록했다. 본 작업은 **통합 자동 생산 완료가 아니라 안전한 준비 상태 진단 및 후속 실행 명세**다. 필수 외부 연결이 검증되지 않아 실제 원고 생성과 게시 파이프라인은 완료로 판정하지 않는다.

기준 브랜치는 `develop`, 시작 커밋은 `1a71681`. 기존 미추적 `.playwright-mcp/`는 보존했다. 운영 DB, Blogger, Google Trends, GPT 예약 작업에는 연결·쓰기·요청하지 않았다.

## 재사용 중인 실제 기능

- Google Trends RSS 파서와 저장 경로는 KR, US, JP, TW, HK, SG를 허용하고 요청당 최대 20개 관측값을 읽는다. 순위는 원천이 주지 않으므로 `null`이다. `collect_geo()`는 호출 시 공유 외부 정책과 영속 시간당 12회 상한을 확인한다.
- Trends 수집은 API에서 호출 가능한 기능이나 Worker의 `worker.py`는 시간별 6개 지역 실행 일정을 만들지 않는다. 동일 시간대 지역별 실행을 예약하는 영속 스케줄 테이블도 없다.
- P5-CODEX-011의 `woori-scheduled-content-import/1.0` 파일 수신, 원자적 `.ready.json` 규약, 최대 4개 처리, 재시작 복구, 멱등 Import와 예약 원고 출처 감사 이벤트는 존재한다. 이 수신기는 원고 작성기가 아니며 실제 예약 파일도 시험되지 않았다.
- Import는 기존 Content Import 1.0 검증과 결정론적 품질·SEO·HTML 평가를 재사용한다. 평가값은 외부 파일에서 신뢰하지 않는다. 사실·출처 독립 검증과 사용권 확인은 완료하지 않으며, 사람 검토 대기와 `generation_ready=false`, `publish_ready=false`를 유지한다.
- 게시 Worker는 Fake 전용이다. 실제 Blogger 쓰기 어댑터, 실제 자동 발행 허가 및 공개 게시 URL은 없다.
- 운영 DB 마이그레이션이나 운영 데이터 변경은 하지 않았다.

## GPT 예약 작업 지원 범위

2026-10-29에 확인한 OpenAI 공식 문서는 예약 작업 생성·일정 관리 및 계정별 기능 차이를 설명한다. Plus의 동시 활성 작업 한도는 5개이며, 시간별/정확한 시간 일정은 해당 플랜에서 지원된다. 프로젝트 내 예약 작업은 프로젝트에 업로드·저장된 파일을 읽을 수 없다. 이벤트 기반 예약은 문서상 Gmail, Slack, GitHub 등 지원 앱에 한정된다. Desktop Work는 권한을 허용하면 로컬 파일을 다룰 수 있지만, 공식 문서는 이 프로젝트 계정의 반복 예약 실행이 로컬 감시 폴더에 안정적으로 JSON을 쓰는 것을 보증하지 않는다.

따라서 5개 예약 작업 초안(한국·미국·일본·중국 시장 마감 각 1개, 주간 금융 1개)은 운영 계정에 생성하지 않았다. 계정 UI에서의 실제 실행, 지정 폴더에 대한 파일 생성, 작업 결과의 출처 진실성은 미검증이다. 5개 초안은 Plus 문서상 활성 작업 수 상한과 같으므로 추가 예약 작업을 계획할 경우 기존 작업 상태를 사용자가 먼저 검토해야 한다. 이 계정의 모델·일정 가용성을 추정하지 않는다.

## 시장 마감과 주간 금융의 차단 이유

현재 승인된 외부 출처 목록에는 거래소별 공식 종가·지수 구성 데이터 제공자, 공휴일/조기 폐장 달력 어댑터가 없다. 각 시장의 지수 값·기준 세션·발표 시각·재배포 권한을 검증할 수 없으므로 KOSPI/KOSDAQ, S&P 500/Nasdaq/Dow, Nikkei/TOPIX, 상하이/선전 시장 수치 원고는 생성하지 않는다. 날짜의 평일 여부만으로 거래일을 판정할 수도 없다.

Fed·SEC 자료 수집 코드는 일부 존재하지만, 이는 신규 문서 식별, 주간 1~3건 선별, 주제 중복 제거, 국가별 독립 원고 작성 또는 게시 승인까지 이어지는 주간 예약 파이프라인이 아니다. 해당 코드를 넘어선 수집이나 권리 판단을 완료했다고 표시하지 않는다.

## 다음 단계(P5-CODEX-013) 실행 순서

1. 사용자가 ChatGPT Scheduled 화면에서 작업 한도와 다섯 작업 초안을 직접 확인한다. 처음에는 한 개의 격리 시험 작업만 만들고, 작업 결과를 사람이 저장한 뒤 `.local/gpt-scheduled-import/ready/<content-id>.ready.json`에 원자적으로 배치하는 수동 전달을 사용한다.
2. 격리 DB에서 해당 파일을 `scripts/import-scheduled-content.py`로 시험한다. JSON의 schema, locale, 등록 Blogger 대상, occurrence 멱등성, 실패 디렉터리와 감사 이벤트를 확인한다. 실제 계정 파일 접근이 증명되기 전에는 Work가 폴더를 직접 쓴다고 설정하거나 주장하지 않는다.
3. 시장 마감 자동화보다 먼저 거래소별 공식 달력 및 값 출처의 무료 이용·재배포 조건을 검토하고, 승인된 어댑터와 최신 세션 검증을 마련한다. 조건을 증명하지 못하면 시장 원고를 계속 보류한다.
4. 시간별 Trends Worker는 격리 DB의 영속 occurrence/중복 방지, 6지역 fan-out, 12 요청/시간 공유 제한, 전체 후보 4건/시간 상한, 일시 중지 및 감사 상태를 구현하고 통합 시험한다. 운영 활성화는 별도 점검 후 수행한다.
5. 생성 Provider가 연결되지 않은 동안 요청 상태는 대기로 유지한다. 외부 원고는 Import와 사람 검토를 거쳐도 운영 `publish_ready`를 자동 변경하지 않는다. Mock 게시와 실제 Blogger 쓰기는 계속 분리한다.

## 검증 및 Git

이번 변경은 문서만 추가한다. 코드 테스트는 실행하지 않았다. 공식 문서 조회는 [ChatGPT scheduled tasks](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt), [ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex), [OpenAI scheduled-task walkthrough](https://developers.openai.com/training/walkthroughs/scheduled-tasks)를 기준으로 한다.
