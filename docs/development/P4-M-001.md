## 변경 전 상태 및 원인

Phase 4-L 최종 재평가의 12개 Fed·SEC 원고에서 기계 검사 4건 통과, 8건 보류였다. 실패 항목은 날짜가 포함된 검색어를 내부 ID로 오인한 키워드 검사 5건, `10-Q`의 `Q`를 `Q Apple Inc`라는 고유명사로 추출하거나 원문에 있는 `USD`를 `United States Dollar`로 표현한 것을 미승인 고유명사로 취급한 검사 4건, 직접 인용 1건, SEC 한국어 제목·키워드의 영어 혼입 1건이다. 다수 원고에서 여러 실패가 겹쳤다.

저장 본문 길이는 Fed 519–951자(5건 평균 730.4자), SEC 421–507자(7건 평균 469자)이며 전체 평균 577.9자, 6–7 문단이다. 이는 각각 Fed 자료 1건의 5개 사실과 SEC 공시 1건의 4개 사실에 기반한 짧은 정보 요약이다. 장문 블로그 수준의 독자 가치가 검증된 것은 아니므로 12건 모두 의미 정확성·자연스러움·권리·독자 가치 사람 검토가 필요하다.

SEC 한국어의 Phase 4-L 실추론 기록은 Qwen3 4B Q4_K_M에서 생성 토큰 256개, 호출 5회, 37.14초였다. 256개는 개요와 4개 사실 현지화를 합친 파이프라인 총량이며 본문만의 토큰 수가 아니다. 이번 Phase에서는 재추론하지 않았다.

## 구현 및 원고 평가

- 키워드 규칙은 날짜 형태를 내부 ID로 취급하지 않고 UUID 및 명시적인 pipeline/source/fact ID만 차단한다.
- 고유명사 추출은 `10-Q` 하이픈 뒤의 `Q`가 이름 시작으로 잡히지 않도록 수정했다. 통화 표기 별칭은 입력 근거에 `USD`, `U.S. dollar(s)` 또는 `United States dollar(s)`가 실제 있을 때만 인정한다. 일반적인 고유명사 승인 규칙은 느슨하게 하지 않았다.
- 기존 Phase 4-L 저장 원고 12건은 평가 DB `woori_blog_agent_eval`의 `woori_eval_reader` 역할로 읽기만 하고, 원래 버전·품질 평가·감사 기록은 수정하지 않았다. 새 결정론 재평가 JSON은 [P4-M 결과](P4-M-results-ed018e1e-a01c-4523-9134-b3b293af84ed.json)에 보존했다.
- 동일 저장 본문과 저장 시점 날짜로 재검사한 결과 기계 통과는 4/12에서 10/12로 증가했다. 오탐 9개 검사 결과(키워드 5, 고유명사 4)가 수정되었고 6개 원고가 새로 기계 통과했다. 실제 오류 2건은 그대로 보류다.
- Fed 영어는 원문과 연속 28단어가 겹친다. 직접 인용 검사 기준을 유지했고 quality hold를 유지했다. SEC 한국어 제목/키워드에는 `Apple Inc. 10-Q filed 2026-07-31`가 남아 언어 메타데이터 검사를 계속 실패한다.
- 기존 generation prompt snapshot은 직접 인용·바꿔쓰기 방지 지시를 포함하지 않았다. 평가행의 `p4l-deterministic-recheck-v2`는 원 생성 프롬프트가 아니라 평가 규칙 버전이다. 관련 USD/고유명사 용어집 항목은 없었다. USD 표현은 출처가 USD를 명시하는 경우에만 사실 근거상 통과 처리하며, 현지화의 자연스러움은 계속 사람 검토 대상이다.

## 편집 검토 구현

- `/research`에 Fed·SEC 저장 원고 작업대를 추가했다. 본문 전문, 언어/모델/시각, 검사 실패, 출처·사실·숫자·날짜·키워드, 기존 의견, 버전 이력과 원본/수정본 나란히 보기를 제공한다.
- 검토 시작 이벤트, 원고 수정본, 검토 결과는 append-only로 저장한다. 수정본은 기존 출처·언어로 기존 결정론 품질 게이트를 다시 실행한 결과와 본문 SHA-256을 저장한다. 실패 수정본은 `quality_held`로 보존한다.
- 편집 상태는 미검토, 검토 중, 수정 필요, 검토 기록(미통과), 편집 검토 통과로 표시한다. 편집 검토는 Blogger 발행 승인과 분리했다. 실제 사용자의 검토를 자동으로 생성하지 않았으며 검토 기록·이벤트·수정 버전은 실제 DB에서 모두 0건이다.
- 신규 migration `029_editorial_versions_and_progress.sql`은 전용 운영 DB `woori_blog_agent`에만 적용했다. 적용 전 DB와 역할을 확인했고 버전 28에서 29로 이동했다. 평가 DB는 별도 읽기 전용 접속만 사용했다.
