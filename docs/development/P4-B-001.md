## Implementation

- Migration 026 adds UTC schedule lifecycle metadata, IANA display timezone, lease/attempt/backoff fields, mock scenario, attempt kind, append-only schedule events, and the `publication_worker` heartbeat name. The evaluation DB provisioning policy excludes Blogger/OAuth credentials and publication tables before explicitly seeded offline fixtures.
- `ScheduleInput` rejects naive/past times and requires the submitted offset to agree with its IANA timezone. Schedule/reschedule/cancel events are idempotent and append-only. Dashboard labels these as mock scheduling; the request's domain state remains quality-held or review-pending, and cancellation is explicit.
- `publication_worker.tick()` claims only due `simulation_only=true` and `adapter_type='fake'` jobs with a lease. It calls no network client. Success updates only fake job lifecycle status; the domain publication state and `publishing_records` never become published. Retryable fake timeouts/server failures have bounded backoff; auth failures stop, uncertain outcomes become `uncertain`, and expired leases are recovered within retry limits.
- `scripts/publication-worker.py --evaluation` requires separate physical evaluation DB validation. `--operations-mock-only` is separately constrained to the dedicated `woori_blog_agent` DB and Fake-only schema rows.
- Read-only sync is paginated via existing `blogger_service.posts()` and its free-provider policy/rate limiter. It returns metadata and internal match status, appends a sync audit, excludes fake rows, and makes no internal-state changes on discrepancies. Dashboard shows remote post metadata and a next-page action.
