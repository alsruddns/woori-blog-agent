# Phase 3.8-B — Evidence-preserving multilingual localization

- **Work ID:** P3-8B-001
- **Date:** 2026-10-26 (Asia/Seoul)
- **Reason:** Phase 3.8-A Korean evidence template failed language checks because source-language English quotes were presented as Korean prose; existing glossary entries had no official-source approval or immutable revision history.
- **Previous state:** Evidence was split only in memory. Source language was not captured on source records/reviews. Glossary terms could be upserted and immediately sent to AI without approval provenance. Dashboard had no fact-level comparison.
- **Purpose:** Persist source-independent fact snapshots and source-language attribution; use only approved official glossary mappings; translate one exact excerpt with a local-only provider; hold uncertain output; preserve evaluation history.
- **Changed state:** Added migrations 016–018 for source language, immutable glossary revisions/backfill, exact source-span facts and append-only localization evaluations. Added review-language attribution as a new review event instead of rewriting old sources. Added dynamic BCP 47 checks, a bounded llama.cpp JSON translation helper, fact-level localizer and evidence-only draft composer. Added authenticated research routes and dashboard comparison/history views.
- **Existing data:** PostgreSQL migration was applied to the dedicated `woori_blog_agent` database. Migrations are sequential and re-runnable; no other project database was accessed. Historical glossary entries are explicitly unapproved. Historical source-language values remain `und` until reviewed.
- **Evaluation:** `docs/development/P3-8B-evaluation.json` stores eight append-only evaluations on two exact fact spans from the saved Federal Reserve source. Phase 3.8-A's English template passed, while its Korean template failed language metadata. With Qwen3 4B Q4_K_M (llama.cpp b11889, Vulkan binary, 20 requested GPU layers, 4 threads), deterministic name placeholders and inherited-year date normalization, all eight fact-level checks passed. This is a machine-check improvement on a two-fact sample; semantic accuracy, translation naturalness, and full-article quality are **not** confirmed. The 3.8-A full drafts and these 3.8-B fact spans differ in output size, so their pass rates are not directly comparable.
- **Measured results:** English exact-span output: 2 facts, 0 AI calls, under 1 ms each. Korean: 2 calls, 14,127 ms total (7,064 ms mean). Simplified Chinese: 2 calls, 12,249 ms total (6,124 ms mean). Japanese: 2 calls, 14,234 ms total (7,117 ms mean). Across all: 6 local inference calls and 8/8 mechanical checks passed. llama.cpp process RSS after calls was approximately 3.39–3.42 GiB. Single post-call CPU samples were about 27–28% of machine capacity. The Vulkan Engine counter sampled 0.0%; GPU utilization is therefore unconfirmed despite Vulkan/20-layer configuration. Token throughput was not measured. Each candidate remains human-review-required and `publish_ready=false`.
- **Observed defects and fixes:** The first Korean result translated `Federal Reserve Board`; it was held. The provider now replaces recognized source entities with deterministic placeholders and restores the exact original name, or an approved official glossary term only. A multi-date translation initially tripped a parser false positive because the source attached the year only to the final date; after confirming equivalent dates, both source and target parser paths now inherit one unambiguous year per sentence. Regression tests cover both fixes.
- **Test result:** Final `scripts/verify.ps1` passed: 97 tests, ruff, mypy, compileall, isolated wheel build, Next.js lint, typecheck, production build and `git diff --check`. PostgreSQL migration 018 was applied and rerun idempotently. Paid-service and Blogger write blockers remain covered.
