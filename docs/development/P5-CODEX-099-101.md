## 실제 시작 중 발견한 후속 결함

첫 수정 `11b47d9`로 예약 작업을 실행하여 API PID3596이 정상 HTTP200으로 시작했다. 그러나 native PowerShell 파이프는 종료된 시작 자식의 백그라운드 API runner가 상속한 핸들 때문에 끝나지 않아 coordinator PID2912가 대기했다. 해당 API는 정상 유지하며 강제 종료하지 않았다.

`Invoke-StartupProcess`를 stdin/stdout/stderr 파일 리디렉션 + Process Handle 사전 확보 + launcher PID에 대한 bounded WaitForExit로 수정했다. `Start-Process -Wait`의 자식 트리 대기도 사용하지 않는다. 90초 내 종료되지 않은 launcher는 오류로 보고하고 그대로 보존한다. null ExitCode를 성공으로 처리하지 않는다. 실패17/성공0 종료코드 및 살아 있는 detached 자식과 독립적인 반환을 실제 임시 PowerShell로 검증한다. 원고/네트워크 테스트용 프로세스는 만들지 않는다.

기존 멈춘 예약 coordinator에 대해서는 정상 API까지 종료할 수 있는 작업 취소를 임의 수행하지 않고 사용자 선택을 요청했다. 이후 새 스크립트 호출의 수정 성공과 기존 실행 인스턴스의 잔여 상태를 구분해 보고한다.
