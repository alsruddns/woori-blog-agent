## 변경 전 상태 및 원인

Phase 4-J/K의 저장 원고는 사실 원장 및 용어집 연결을 이미 사용했지만, 로컬 번역 요청에서는 기관명만 placeholder로 보호했다. 숫자·날짜 보존은 프롬프트와 사후 규칙 검사에 의존해 모델이 값을 바꾸거나 누락할 수 있었다.

저장된 생성 결과 12건(Fed/SEC, 기준 Qwen3 4B 및 기존 평가 전용 Instruct 후보)을 결정론적으로 평가했다. 이전 검사기에서 `no_unverified_numbers` 실패 4건이 확인되었다. 그중 한 실제 SEC 한국어 원고는 `2026-07-31에`처럼 ISO 날짜 뒤에 한국어 조사가 붙은 표기가 `2026`, `7`, `31` 세 숫자로 읽히는 검사기 오탐이었다. 같은 원고의 번역은 날짜를 원문과 동일하게 보존했다. 제목·키워드 언어 불일치와 일부 언어의 미승인 고유명사·출처 중복 실패는 생성/콘텐츠 문제로 분리했다.

Phase 4-K에 기록된 Fed 영어 후보의 28단어 연속 원문 겹침은 25단어 한도를 넘은 실제 직접 인용/복제 위험으로 유지했다. 기계 검사에서 판단할 수 없는 의미 정확성, 자연스러움, 독자 가치는 사람 검토로 남겼다.

## 구현 내용

- `local_inference.localized_translation`은 인식한 전체 날짜 구간과 숫자 토큰을 타입별 고유 placeholder로 보호한다. 각 placeholder가 정확히 한 번 돌아오지 않거나 원문에 예약 placeholder가 있으면 실패 처리한다. 복원 후 잔여 marker도 차단한다. 공식 명칭 및 승인 용어집 보호는 기존 로직을 유지한다.
- `grounding.numbers`의 ISO 날짜 경계를 ASCII 문자 기준 lookaround로 바꾸었다. 날짜 바로 뒤에 한글 조사 등 로컬 문자가 붙어도 날짜 전체를 인식하며, 다른 날짜·수치 값은 여전히 구별된다. 날짜 표시 형식의 변환은 모델에 맡기지 않는다.
- `/research`의 근거 보존 현지화 화면에 사실 원장의 보호 숫자·날짜를 원문 구간 옆에 표시한다. 기존 용어집 승인 상태와 append-only 변경 이력, 모델 비교, 사람 검토 상태를 재사용했다.
- `scripts/recheck_p4l_evaluations.py`를 추가해 평가 전용 DB에서 최신 저장 Fed/SEC 결과를 결정론적으로 다시 검사하고 새 불변 `article_quality_evaluations` 및 감사 이벤트를 기록한다. 기존 버전·평가·감사 행은 변경하지 않는다. 실제 추론, 외부 호출, quota 소비는 없다.
- 스키마 변경은 없다. 운영 DB 변경은 없다.

첫 조회에서 주제 키워드 필터가 Apple SEC 기록만 선택한 것을 확인해, source snapshot의 검토된 출처명을 기준으로 남은 Fed 결과를 별도 append-only 평가했다. 최종 v2 평가는 동일 버전·언어·모델 조합의 최신 저장 결과 12건을 포함한다.

최종 결정론적 재평가 결과는 4건 기계 검사 통과/사람 검토 필요, 8건 품질 보류/사람 검토 필요다. v1 결과에서 날짜 파싱에 따른 `no_unverified_numbers` 실패가 4건 있었고, v2 결과에서는 0건이다. 남은 실패는 다음과 같다.

기존 콘텐츠 그룹 상태와 실제 원고는 수정하지 않았다. 새 평가 기록 24건(첫 v1 재평가 12건과 corrected v2 12건)을 evaluation DB에 추가했다. `publish_ready=true` 평가 행은 0건이다. 사람 검토는 0건 완료, 12건 대기다.
