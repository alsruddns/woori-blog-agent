- Work ID: P3-9-001

- Reason: Phase 3.8 established fact-first generation and immutable article evaluations; Phase 3.9 adds observable Worker health and a bounded, append-only evaluation entry point.
- Existing issue: the dashboard showed queued jobs and quality rows but did not distinguish a live Worker from a stopped or stale one.
- Objective: expose truthful Worker freshness and database-backed operations summaries, retain machine/human review separation, and verify restart/retry behavior without touching unrelated queued jobs or starting constrained inference.
- Before: no durable Worker heartbeat; prior C2 deterministic recheck was tied to one output filename.

## Implementation

- Added `worker_heartbeats` as a mutable current-state projection. The local Worker refreshes it every 15 seconds on a separate daemon thread so a long inference does not make a healthy process appear dead. Status transitions are appended to `audit_events`; secrets and raw exception text are excluded.
- Added the authenticated research-state payload with actual counts by job/content/evaluation state, recent failure categories, and heartbeat freshness. The dashboard displays these database values and explicitly treats missing/stale heartbeat as unknown.
- Added `scripts/run_phase39_quality_evaluation.py`, reusing the deterministic article evaluator. It reads the immutable Phase 3.8-C1 batch, appends evaluation and audit rows, saves a unique JSON artifact, and makes no model or external calls.
- Documented startup/stop and recovery commands. Windows Task Scheduler registration and OS reboot were not performed.
