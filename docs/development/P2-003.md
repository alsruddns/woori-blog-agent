# P2-003 — 실제 Blogger 읽기 연결 검증

- 작업 일시: 2026-10-26 12:07–12:25 Asia/Seoul. 정확한 커밋 시각은 Git 기록 참조.
- 변경 사유·목적: 사용자 Google OAuth 읽기 동의 완료에 따라 Phase 2 실제 연결을 검증하고 읽기 실패를 해결한다.
- 기존 문제·변경 전 상태: OAuth 연결은 존재했지만 네 블로그의 원격 ID/연결 검증은 미완료였다. 첫 실제 게시글 목록 요청이 HTTP 400 invalid_request로 실패했다.
- 원인: 첫 페이지에서 선택 매개변수 pageToken을 빈 문자열로 전송했다. 동일 AUTHOR/view/status 조건에서 빈 매개변수를 제외한 후 실제 요청이 200으로 성공했다.
- 변경 후 상태: 네 블로그 실제 ID/URL/계정 접근을 검증해 기존 DB 행에 저장했다. 첫 페이지에는 pageToken을 생략하고 다음 페이지 토큰만 전달한다. Google이 items를 생략하면 API는 items=[]를 반환한다. 성공한 게시글 조회도 last_checked_at을 갱신하고 이전 오류를 해제한다.

## 실제 Google 검증

인증 연결 1개의 암호화된 Access/Refresh Token을 사용했다. 유효한 Access Token으로 GET 요청이 성공했고, 저장된 권한은 blogger.readonly 하나다. Google 계정 비밀번호·토큰·사용자 이메일·인증 코드·원문 오류는 출력하지 않았다. 인증된 계정의 users/self/blogs가 아래 네 블로그를 모두 반환했다. Blog ID는 Google 응답에서만 가져왔다.

| 언어 | 등록 URL | 실제 Blog ID | 실제 제목 | 게시글 GET | 검증 시각 KST |
| --- | --- | --- | --- | --- | --- |
| ko | https://trend-ko.blogspot.com | 3321654108096579717 | Trend Journal / 트렌드 저널 | 200, 0개 | 12:15:33 |
| en | https://trend-journal-en.blogspot.com | 5240203250707821039 | trendJournal | 200, 0개 | 12:15:21 |
| zh-CN | https://trend-zh.blogspot.com | 1931836538202286191 | Trend Journal / 趋势观察 | 200, 0개 | 12:15:40 |
| ja | https://trend-ja.blogspot.com | 7562596540375659150 | Trend Journal / トレンドジャーナル | 200, 0개 | 12:15:28 |

표의 `/`는 제목에 포함된 세로 구분자 `|`를 문서 표에서 표시하기 위한 표기다. Google URL의 마지막 `/` 차이를 제외하면 등록 URL과 일치하며 DB 언어 코드 매핑도 일치한다. 각 목록은 한 페이지에서 종료하고 nextPageToken이 없었다. 실제 게시글이 없어 실제 다중 페이지/상세 조회는 검증할 대상이 없다. 다중 페이지 전달은 Mock으로 검증했다. 이후 실행 중인 Next 프록시에서도 네 목록을 재조회해 모두 200/items=[]를 확인했으므로 DB last_checked_at은 위 시각보다 이후로 갱신될 수 있다.

API 호출은 기존 blogger_api_calls와 audit_events에 요청/성공/실패를 기록했다. 최초 400 기록을 보존했고, 수정 후 성공 기록을 추가했다. 별도 blogger.verification.started/completed 이벤트가 블로그별 1건씩 생성됐다. 계정 목록은 blog_id/language_code를 NULL로 기록하여 특정 언어의 요청으로 위장하지 않는다. 계정 목록은 계정별 분당 30회, 블로그 읽기는 기존 DB 언어별 제한 및 최대 3회 요청 예산을 적용한다.

## 실제 검증과 Mock 검증 구분

- 실제: readonly 권한, 계정 블로그 목록, 네 블로그 getByUrl/get, AUTHOR 게시글 목록, URL/ID/언어 대조, 빈 마지막 페이지, DB 연결 저장/시각 갱신, 감사 이벤트, Next→FastAPI→Google GET 프록시.
- Mock: OAuth state/바인딩/재사용/만료/취소, 암호화/잘못된 키/갱신/토큰 취소, 401 재인증 1회, 403 권한 부족, 429·5xx·네트워크 재시도 제한, 다음 페이지 토큰 전달, Mock 쓰기/중복·불확실 결과 차단. 실제 인증을 고의로 취소하거나 권한을 훼손하지 않았다. 실제 Refresh Token 갱신은 이번에 강제로 수행하지 않았다.
- 다국어: 롤백되는 DB 통합 테스트로 추가 BCP 47 언어, 동일 언어 복수 블로그, 정책/카테고리/비활성화 및 기존 이력 보존을 검증했다. 실제 운영 설정에 테스트 언어를 남기지 않았다. 검증 스크립트는 DB의 활성 언어/블로그를 조회하며 네 언어/URL/ID를 하드코딩하지 않는다.
- 안전: Google 네트워크 요청은 GET 및 기존 OAuth 경로만 사용한다. 운영 게시글 생성·수정·삭제·자동 발행과 유료 AI는 계속 차단된다. 기존 콘텐츠/발행/감사 기록을 삭제하지 않았다. 다른 프로젝트/DB는 수정하지 않았다.

## 검증 결과

- Python: ruff check, mypy(13개 소스), pytest 50개 통과.
- Next.js: ESLint, 타입 검사, production build 통과.
- 마이그레이션: 기존 migrate.py 재실행으로 Migration 006 verified. 새 스키마 변경 없음. 런타임 계정의 schema_migrations 직접 조회가 거부되는 최소 권한도 유지했다.
- 실제 Dashboard /, /config, /blogger 200; API /health 200; 관리 API 무인증 401; 동일 출처 Blogger 상태 프록시 200/writes_enabled=false.
- 인증 바인딩 없는 실제 callback은 303 /blogger?oauth=failed, HttpOnly 쿠키 삭제(Max-Age=0), Referrer-Policy=no-referrer. 사용자가 완료한 실제 OAuth 연결은 정상이며 이 음성 테스트로 해제하지 않았다.
- 감사/API 이력과 실제 HTML/API 응답을 메모리 내 복호화한 비밀값과 대조하여 평문 노출 없음. publishing_policies.auto_publish_allowed 및 language_execution_limits.publishing_enabled 활성 행 0개.
- 보조 검증 쿼리의 잘못된 컬럼명(auto_publish)은 실제 컬럼 auto_publish_allowed로 수정했다. 런타임 권한으로 마이그레이션 이력을 읽으려던 검사는 별도 마이그레이션 실행 결과로 대체했다. 애플리케이션 장애나 권한 확대는 없었다.
- Windows cp949 출력에서 일본어 제목 인코딩 실패가 있어 검증 스크립트 stdout을 UTF-8로 지정하고 재검증했다.
