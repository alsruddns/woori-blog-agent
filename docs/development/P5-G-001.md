# P5-G-001 — Blogger OAuth writer permission

- Work ID: P5-G-001
- Date: 2026-10-27 Asia/Seoul
- Branch: develop
- Reason: provide a user-driven path to grant a separate Blogger management scope while retaining established read-only credentials and mappings.
- Existing issue: OAuth requested and accepted only `blogger.readonly`; callback assumed that scope and the Dashboard exposed no write-scope consent action.
- Change purpose: add a separate write-permission OAuth flow with exact granted-scope validation and clear Dashboard status without enabling Blogger writes.
- Before: one read-only flow, fixed read scope, existing connected rows and blog mappings.
- After: read and writer scope flows create separate connection rows; requested scopes are bound to OAuth state; the Google callback validates the granted scope; tokens remain encrypted; refresh keeps the prior refresh token if Google does not rotate it; failures affect only the new connection. Blog mappings are not automatically reassigned. The Dashboard shows permissions and token expiry from returned scope/connection data without claiming Google account identity or successful write access.
