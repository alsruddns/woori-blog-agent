# P5-UI-001 ? Dashboard content workspace redesign

Date: 2026-10-28 (KST)
Branch: `develop`

## Purpose and starting point

The previous `/research` page combined manuscript bodies, source observations, model results, phase status, audit data, and operational controls in a long page. It refreshed the complete state every five seconds. This change reorganizes the existing capabilities around content work while retaining the `/research` URL as a compatibility redirect.

## Implementation

- Added a concise content-operations landing page and navigation for sources, manuscripts, model comparison, publishing, automation, and operations/diagnostics.
- Added paginated manuscript list and selected-manuscript detail read models. The list response contains bounded metadata and review/publication summaries, not manuscript bodies or quality JSON. Full text, evidence, checks, sanitized editorial versions, review history, and approval history load only after selection.
- Kept review, revision, and publication approval writes on the existing endpoints. Read-only historical results are visible, but edit/review controls are only presented where the existing Phase 3.9-T eligibility policy allows them. Every result still reports `publish_ready=false`.
- Added paginated Google Trends observation browsing, topic/source/fact/package detail, and explicit null display for source values that were not provided. Added stored model comparison browsing without generating substitute results.
- Added Korean labels, KST date formatting, title ellipsis/tooltips, keyboard row selection, focus-managed manuscript detail dialog, Escape close, focus trap, scroll lock, responsive full-screen mobile detail, and constrained horizontally scrollable tables.
- HTML article content uses the existing server sanitizer and a sandboxed preview iframe with restrictive CSP. Markdown text is escaped before rendering. Diagnostics JSON is folded by default.
- No database migration was added or applied. No AI inference, Blogger request, operational content write, or paid provider call was made.

## Read-only runtime evidence

API endpoints were exercised using the current configured databases through FastAPI TestClient with authenticated GET requests:

- Manuscript list: HTTP 200, 18 records. The list projection has no body, saved body, metrics, or checks fields.
- First manuscript detail: HTTP 200; full body and quality data were present; historical `phase4l` item had review actions disabled and `publish_ready=false`.
- Trend observations: HTTP 200, 0 records. The existing six-region collector data is therefore not currently present in the queried operations database; no region is represented as having observations.
- Model comparison: HTTP 200, 36 records. Stored results are local Qwen3 evaluation variants across the recorded languages. There are no NVIDIA Build comparison records, so the UI reports that absence.

A read-only operations DB identity/count query returned database `woori_blog_agent`, role `woori_app`, 360 `content_versions`, 1,421 `audit_events`, and 0 `publication_approval_events`. The count query did not alter data. The `publish_ready` column is not part of `content_versions`; publication readiness is kept fail-closed by the manuscript API response.
