## 설정 확인

3100과 8100의 LISTEN 상태를 먼저 확인했으며 이전 작업에서 시작한 이 프로젝트의 Dashboard/API 프로세스가 루프백에서 사용 중이었다. 다른 프로젝트 프로세스를 종료하거나 포트를 변경하지 않았다.

- Next.js dev/start: 127.0.0.1:3100.
- FastAPI 실행 스크립트: 127.0.0.1:8100, access 로그 비활성화.
- 서버 전용 API Base URL: http://127.0.0.1:8100.
- Google redirect URI: http://127.0.0.1:3100/api/blogger/callback.
- PostgreSQL: 기존 5432 유지.
- 프록시 Host/Origin, 콜백 쿠키 경로, 환경 예제, 스모크 테스트, README, 운영 가이드에 새 포트가 반영되어 있음.
- 소스의 남은 3000 값은 요청 제한 시간 3000ms 또는 이전 Origin 차단 테스트/기존 포트 설명이며 실행 포트가 아님.

## 테스트 결과

이번에는 DB 쓰기 없이 실제 실행 중인 서비스를 검사했다.

- Dashboard /, /config, /blogger: HTTP 200, HTML에 관리자 토큰 없음.
- API /health: HTTP 200, status=ok.
- 관리 API 미인증 요청: 401.
- 3100 동일 출처 Blogger 프록시: 200, writes_enabled=false.
- 이전 3000 Origin 및 외부 Origin: 403.
- 언어 설정 프록시의 무효 입력: 422. 유효 설정 변경 요청은 보내지 않음.
- FastAPI OPTIONS에 CORS 허용 헤더가 없음. 브라우저는 동일 출처 Next 프록시를 사용함.
- 인증 바인딩 없는 실제 콜백: 303으로 http://127.0.0.1:3100/blogger?oauth=failed 이동.
- 콜백 쿠키 HttpOnly·Max-Age=0, Referrer-Policy=no-referrer 확인.
- 비밀 환경 파일 4종 Git 제외 및 원격 develop과 HEAD 일치 확인.
- 문서 변경은 git diff --check로 검증. 애플리케이션 코드 변경은 없으며 이전 구현의 48개 테스트·lint·타입 검사·빌드 통과 기록은 P2-001에 보존함.

성공 OAuth 왕복은 P2-001에서 실제 Next/FastAPI 라우팅과 Mock Google 제공자로 검증했다. 이번 실패 콜백 검증을 실제 Google 계정 승인 성공으로 보고하지 않는다. 운영 Blogger 생성·수정·삭제·자동 발행은 계속 차단한다.
