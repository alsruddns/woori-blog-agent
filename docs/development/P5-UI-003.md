# P5-UI-003 — Dashboard 전체 UI/UX 리뉴얼

작성일: 2026-10-29 (KST)
브랜치: `develop`

## 변경 요약

기존 Dashboard는 원고 목록과 외부 제출 원고 검토가 한 화면에 길게 쌓였고, 외부 원고 제목을 눌러도 가져오기 화면에서 다시 원고를 선택해야 했다. 기본 탐색에 진단 기능이 섞여 있었으며 발행 화면의 주요 문구도 영어였다.

상단 메뉴를 `대시보드`, `수집 자료`, `원고 관리`, `발행 관리`, `자동화 관리`, `운영 진단`으로 정리했다. AI 모델 비교는 운영 진단 안에서 계속 접근할 수 있다. 기존 경로는 유지했고 `/research` 호환 경로도 기존 동작을 보존한다. 현재 URL에 맞는 메뉴만 활성화되는지 자동화·운영 진단 경로 회귀 테스트를 추가했다.

원고 관리에는 `작성 원고`와 `외부 검토 대기` 탭을 두고, 가져오기는 별도 작업 버튼으로 분리했다. 기존 서버 페이지네이션과 검색·분야·언어·상태 필터를 유지하면서 선택 조건을 URL에 반영한다. 외부 원고 제목을 한 번 누르면 ID가 포함된 `/imports?open_import_id=…` 주소로 상세 패널이 열린다. 브라우저 뒤로 가기, Escape, 닫기, 포커스 복귀와 목록 상태 보존을 검증했다.

외부 원고 상세 패널을 `원고 편집`, `출처·근거`, `품질·SEO`, `HTML 미리보기`, `다국어·발행`, `변경 이력` 탭으로 구성했다. 저장·검사·검토 등 요청 처리 중에는 탭 전환을 잠가, 비동기 갱신이 완료되기 전에 사용자가 다른 화면으로 이동해 상태가 어긋나는 일을 막았다. 검토와 게시 권한은 기존 서버 규칙을 그대로 사용한다.

`/imports`는 JSON 파일·텍스트 가져오기에 집중하며 최근 이력은 접힌 영역에 둔다. 가져온 원고의 상세는 같은 패널에서 연다. 발행 화면은 한국어 상태 안내와 `승인 대기`, `게시 이력`, `게시 설정` 탭으로 재배치했다. API 오류·서버 오류·빈 상태는 한국어 안내로 표시한다. 실제 발행 잠금과 Manual 기본 정책은 유지한다.

## 화면 검증

Playwright Chromium의 데스크톱 및 모바일 프로젝트에서 원고 목록·필터·페이지네이션, 외부 원고 한 번 클릭 열기, 상세 탭, 뒤로 가기와 Escape, 모바일 전체 화면 패널, 메뉴 활성 상태, 발행 오류 안내, 수집 자료 및 진단 화면을 확인했다. 뷰포트 회귀 검사는 320, 390, 768, 1280, 1920px을 포함한다. 가져오기 통합 흐름은 격리 테스트 DB에서 검증했다. 품질 검사와 Mock 게시 결과는 실제 Blogger 게시와 분리되며 외부 요청은 발생하지 않았다.

가져오기 E2E에서 검사 결과는 결정론적 게이트 통과였으나, 테스트는 원문·주장·권리 항목에 사람 검토 체크를 직접 남긴 뒤 격리 Mock Publisher까지만 진행했다. 해당 실행은 운영 DB가 아닌 `woori_blog_agent_test`에 테스트 원고·버전·검토·Mock 기록을 추가했다. 테스트 기록은 삭제하지 않았다.

발행 관리 화면을 실제 UI에서 열었을 때 테스트 환경의 `/admin/publications` API가 HTTP 503을 반환했다. 화면은 이를 “서버가 발행 정보를 불러오지 못했습니다”라는 오류로 안내했다. 따라서 실제 데이터가 채워진 승인 대기·게시 이력·설정 화면 동작은 검증하지 못했다. Mock 게시 통합은 별도 가져오기 흐름에서 확인했다.

## 검증 및 안전

- `scripts/verify.ps1`: 통과 — Ruff, mypy(38개 소스), pytest 266건, 격리 wheel 빌드, Dashboard ESLint, Next.js production build, TypeScript, `git diff --check`.
- Dashboard Playwright: 주요 탐색·원고 화면 20건 통과(데스크톱·모바일 각 10건).
- 가져오기·편집·버전·품질/SEO·미리보기·검토·Mock 게시·현지화 취소 E2E: 1건 통과.
- `scripts/verify-secrets.py`: 테스트 모드 HTTP 대상으로 통과. 읽기 전용 이력·정책 점검과 HTTP 응답 비밀정보 검사를 수행했으며 비밀값을 출력하지 않았다.
- 운영 DB 데이터 및 스키마를 수정하거나 마이그레이션하지 않았다. 쓰기 E2E는 격리 테스트 DB에만 수행했다.
- 실제 Blogger 게시·수정·삭제 0건, 유료 API 호출 0건. `publish_ready` 및 자동 게시 정책은 변경하지 않았다.
- `.playwright-mcp/`는 기존 미추적 사용자 자료로 보존하고 Git에 추가하지 않았다.

## 화면 접근 및 한계

개발 확인용 Dashboard는 `http://127.0.0.1:13100/manuscripts`, API는 `http://127.0.0.1:18100`에서 실행 중이며 API는 테스트 DB와 평가 읽기 전용 연결을 사용한다. 운영 포트 3100/8100은 건드리지 않았다. 발행 데이터가 필요한 화면은 테스트 API의 503 상태를 표시한다.
