## Implementation

- Reused the existing immutable `evidence_facts` ledger and added the `fact_registry` stage to `generation_stage_runs` via additive migration 022. Original `evidence_extraction` remains in place.
- The worker now verifies each exact registered span, localizes one fact at a time through the local JSON translation adapter, and attaches its citation and article structure in application code. English source facts can use the local adapter for faithful same-language editing; direct same-language copies remain available to existing localization callers.
- Approved glossary entries are selected with their language, provenance and approval fields. Per-fact number/date/entity/script/citation checks are retained in stage output. Localization failures remain held and do not retry a quality-held fact repeatedly.
- The final gate now checks source overlap against the 25-word direct-copy limit and includes per-fact localization results in claim/SEO stage checks. Meaning and naturalness remain human-review requirements.
- Added an evaluation-only override for the already installed `Qwen3-4B-Q4_K_M.gguf`. It does not alter operational model settings, emits an audit event, and uses existing per-profile daily limits, single-worker concurrency and RAM/CPU guards.
- Added `scripts/run_fact_first_evaluation.py`, which reuses its own unfinished Fed/SEC evaluation jobs, refuses unrelated queued work, and never collects sources or calls Blogger. Its JSON artifact creation is append-only.

The worker correctly stopped SEC before inference: it is terminal `failed/daily_generation_limit`, attempts 0, paused, and has no output. The evaluator now checks all profile targets, and its regression test confirms evaluation jobs share the normal daily limit.
