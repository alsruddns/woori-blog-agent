## 오류 분석·해결

1. PowerShell에서 JSON 인수 따옴표가 제거되어 엔진 기동이 실패했다. subprocess 인수 배열과 JSON 직렬화를 쓰는 전용 시작 스크립트로 수정했다. 사용자 시스템 설정은 변경하지 않았다.
2. 모델 로딩 중 health 503을 일반 응답 실패로 처리했다. 로딩 상태를 재시도 가능한 category로 구분했다. 최초 실패 측정은 보존했다.
3. 수집 완료 상태 SQL의 `%s IS NOT NULL` 타입을 결정하지 못했다. 명시적 text cast와 회귀 테스트로 수정하고 임대 복구 후 중복 없이 완료했다.
4. HTML 파서가 사이트 안내/메뉴까지 포함했다. article 컨테이너로 범위를 제한하고 회귀 테스트를 추가했다. 이전 근거는 수정하지 않고 새 revision을 저장했다.
5. 근거 개정 중 실행 중이던 첫 실제 작업 e49a2e7f-3ca1-4e1c-997b-62fc5c1cf2a7이 **evidence_changed로 실패**했다. 이미 저장된 평가 버전 2개는 유지했고 정제된 최신 근거로 최종 작업을 새 키로 실행해 네 버전을 저장했다.
6. 실제 후보가 있는 DB에서 스케줄 통합 테스트가 운영 후보를 선택하려 했다. 테스트 fixture 내부 롤백 트랜잭션에서 기존 후보를 제외하고 모든 설정을 Mock으로 격리했다. 영구 변경이나 실제 모델 호출은 발생하지 않도록 했다.
7. 모델이 해당 언어 문자를 출력해도 제목/키워드는 영어인 사례가 있어 필드별 문자 검사를 추가했다. 숫자 집합 검사는 숫자와 사실 관계를 증명하지 못하므로 의미적 검증은 계속 보류한다.

## 검증·파일·Git·잔여 과제

최종 비밀정보 검사에서 관리자 비밀값의 짧은 문자열이 공개 작업 UUID 일부와 우연히 일치했다. 해당 UUID 문맥만 제외하고 실제 평문 위치와 전체 UUID 형태의 비밀값은 계속 검출하도록 보정했으며 회귀 테스트를 추가했다. 비밀번호·토큰을 출력하거나 관리자/다른 프로젝트 계정을 변경하지 않았다.

자동화 테스트는 기존 전체와 수집 장애/재시도/멱등성, 임의 URL 거부·unsafe XML·본문 범위, 새 수치/URL/언어 불일치, 스트림 취소·모델 identity, Mock의 실제 평가 위장 차단, schema 001→013 보존을 포함한다. Python lint/type/test/wheel, Next lint/type/build, 실제 루프백 API/프록시/화면, 토큰·비밀정보 제외, 운영 쓰기/유료 AI 차단을 최종 확인한다. 정확한 최종 결과는 커밋 보고와 연결한다.
