# 예약 원고 게시 우선 운영 정책 — P5-CODEX-052

## 적용 범위

이 정책은 `chatgpt_scheduled_export`로 정상 수신된 예약 원고와 현재 승인된 예약 Auto 블로그 범위에만 적용한다. 일반 수동 원고와 Google Trends 기반 원고의 사람 검토·승인 규칙은 변경하지 않는다. 전역 `publish_ready`나 일반 Auto 설정을 바꾸지 않는다.

## 게시 전 필수 게이트

- 원고 버전과 본문 hash가 고정되고, 언어·대상 Blogger·예약 원고 provenance가 일치해야 한다.
- 게시에 남기는 사실 문단은 출처 marker가 있어야 한다. 각 주장은 실제 현재 원문에서 확인된 근거 구간과 연결되고 수치·단위가 일치해야 한다. `corroborated` 표시는 서로 다른 두 기관 근거가 있어야 한다.
- 출처 문서의 HTTP 응답, 정규 URL, 원문 hash, 근거 구간은 Import 자기 선언과 분리해 확인한다.
- 근거가 없거나 `unverified`인 주장, 숫자 불일치, 출처 미접근, 명시적 권리 제한, 원문 복사, 직접 인용, 임베드 이미지는 새 불변 원고 버전에서 제거하거나 게시를 보류한다. 수정 전후 hash와 제거한 block hash, 사유, retained claim/source IDs 및 검사 결과를 감사 로그에 추가한다.
- 보정 후 독립적으로 읽을 수 있는 본문이 2개 미만의 사실 문단 또는 100자 미만이면 게시 Job을 만들지 않는다.
- SEO·문장·번역 표현의 사소한 개선, 비핵심 추가 출처·환율·기준일 확인 등은 게시 후 보완 항목으로 만들 수 있다. 이는 핵심 사실, 권리 문제, 중복, 블로그/언어 불일치의 예외가 아니다.
- 모든 수집·평가·발행 한도, OAuth, 중복, 멱등성, emergency stop, Blogger 원격 GET 검증은 계속 적용한다.

## 저작권·이용조건

사실 검증과 재사용 권리를 별개로 평가한다. 승인된 현재 원문에서 사실을 확인하고, 원고가 독창적 요약이며 검증 excerpt를 그대로 싣지 않고, 직접 인용과 이미지·표 복제가 없을 때는 미확정 재사용 조건을 medium 심층 확인 항목으로 남길 수 있다. 명시적인 금지·제한, 원문 복제, 출처 접근 불가 또는 인용 사용을 판단할 증거가 불충분하면 자동 공개하지 않는다. 이 운영 기준은 법률 자문이나 권리 보증이 아니다.

## 최초 공개 및 이후 처리

최초 공개 글에는 기존 UI/API의 명시적 승인 이벤트가 필요하며, 승인 대상은 정확한 Import ID, import/content version, 본문 SHA-256, Blogger blog ID에 묶인다. 이후에는 승인된 예약 Auto 범위에 속한 검증 통과 예약 원고마다 별도 버튼을 요구하지 않는다. 예약 Auto 자체가 OFF/철회된 경우, 전역 emergency stop 또는 외부 Blogger write approval이 없으면 쓰기는 차단된다.

## 게시 후 보완 기록

기존 schema 53/54의 `post_publication_reviews` 및 `post_publication_review_items`를 재사용한다. Job 생성 시 보완 row와 issue를 미리 저장하고, 실제 Blogger LIVE GET이 성공하면 publishing record·post ID·공개 URL에 연결한다. 게시 실패 또는 불확실 상태에서는 해당 항목을 공개 게시 완료로 표시하지 않는다. 기존 행과 감사 이벤트는 삭제·수정으로 정정하지 않는다.

## 정책 변경 이력

P5-CODEX-032 초안과 기존 예약 예외는 사전 사람 검토 및 hash-bound 재사용 약관에 과도하게 의존해 사소한 보완 이슈까지 전체 게시를 차단했다. P5-CODEX-052는 예약 Auto lane에서만 문제 주장/문단을 제거하고, 핵심 증거가 남는 원고의 사소한 보완을 게시 후 관리하도록 명시한다. 사람 승인 기록을 생성하거나 `publish_ready`를 true로 설정하지 않는다. 변경·활성화·보정 결과는 운영 감사 이벤트에 append-only로 기록한다.

## 현재 실제 운영 상태

문서 정책은 runtime 설정을 자동 변경하지 않는다. 예약 Auto 활성 상태, 첫 게시 승인, 외부 Blogger write approval, 현재 원고의 자격은 운영 DB/API의 실측 결과로 확인해야 한다.
