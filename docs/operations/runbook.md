Backups contain content/audit data and must be encrypted and copied off-device with access controls. Archive catalog validation is not a restore rehearsal.

### Managed local server lifecycle

Run `scripts/status.ps1` before changing any service. It lists listener PID, executable, start time, and whether the process can be tied to this checkout. `scripts/start.ps1 -Service api` or `-Service dashboard` refuses occupied ports, launches the existing project runner in a visible PowerShell window, records its PID under ignored `.runtime/servers.json`, then verifies a read-only HTTP GET (API `/health`, Dashboard `/research`). The 2026-10-27 cutover started the current develop API on 8100 and Dashboard on 3100 through this manager; both returned HTTP 200, and the API state BFF exposed the Migration 033 approval fields. `scripts/stop.ps1 -Service api|dashboard` accepts only a recorded PID whose executable, runner path, checkout path, and start time still match; it refuses active TCP clients and requests normal window close. If no graceful channel exists or the port remains occupied, use Ctrl+C in the original service terminal. The script never force-kills and keeps PID records until the process and listener are both gone. `scripts/restart.ps1` cancels start if graceful stop is not confirmed.

The existing 3100/8100 listeners predate this manager, so no PID control record exists. The manager reports them as unmanaged and will not stop them. To move a future server under management, first stop it with Ctrl+C in its original verified project terminal, confirm the port is free with `status.ps1`, then use `start.ps1`. Local Qwen3/llama.cpp management has been retired: there is no model status/start/stop command or local inference port managed by this project. Existing `.local` model files and shared engine binaries are user-managed and are not deleted by repository scripts. Do not use a port-only PID as authority to terminate any process.
