# Zero additional cost policy

Reviewed on 2026-10-27. The application has a zero currency budget for external services. It never treats an API key, free trial, credit, or quota as permission to incur a charge. It must stop when a local limit or provider quota is reached, and must never switch to a paid provider, proxy, tier, host, or model.

## Shared outbound gate

All backend HTTP clients for remote services use `woori.external_policy.client`. The gate checks the provider and operation allowlist, HTTPS, exact host, method, path prefix, proxy-free environment, local per-provider call cap, suspicious credential names, and a terms review expiry. Redirects are disabled by default; the explicitly invoked artifact installer follows redirects through the same host/path gate. Unknown providers, custom live transports, expired reviews, suspicious billing credentials, audit write failures, and disallowed destinations fail closed.

Each outbound request appends metadata-only `external.call.started` and `external.call.completed` events. Quota stops append `external.call.quota_stopped`. Events omit query strings, headers, request/response bodies, tokens and credentials. The runtime dashboard reports only suspicious variable names, never values. Local model inference has been retired; there is no fixed loopback model endpoint or active inference runtime.

The gate caps requests per provider per minute and per hour in-process. Taiwan official document retrieval additionally reserves each call against an append-only audit-backed rolling-hour cap under a database advisory lock, so restarting the process cannot reset that provider's hourly budget. Existing durable collector quotas remain in force. A provider HTTP 429 or recognized quota response is a hard stop with no retry. Transient 5xx and network retries remain bounded only where an existing client supports them; no retry can route to another provider. Callers must not add a fallback when handling these errors.

## Billing credentials and review

Before every remote request the gate checks process environment variables and project `.env*` files for known paid AI, cloud, payment, and proxy credential/configuration names. If any nonempty match appears, remote calls stop and the authenticated research state lists the variable names only. The user must remove the setting or explicitly revise the policy after a cost review; the application never reads or prints the value for this report. Existing `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` for Blogger OAuth and database URLs are not classified as billing credentials. A Google API key, Cloud credential, billing setting, API key for a paid AI provider, or proxy setting is classified as a blocker.

## Blogger-only owner cost attestation (2026-10-27)

The project owner explicitly attested in the user instruction that Blogger API use is free for this project and requested a narrowly scoped exception to the previous `provider_cost_unverified` block. This is an owner-provided policy decision, not independent evidence that Google's pricing or the linked Cloud Billing account was examined. Runtime access requires an append-only `external.blogger.cost_policy.approved` audit event written by `scripts/record_blogger_cost_attestation.py`; the runtime does not hard-code the Blogger provider as reviewed. The event records the approval time, evidence type, before/after policy state, and exact scope.

The exception applies only to the Blogger provider and currently enables blog/post reads plus a user-confirmed private draft insert for the four registered test blogs. The policy layer recognizes a narrowly scoped, user-approved existing-post PATCH/PUT operation, but this phase does not expose or execute a live update workflow; existing posts were not modified. Blogger DELETE, publish, schedule, automatic publishing, and `publish_ready` remain disabled. The existing local caps (30/minute, 120/hour), Blogger language request limits, no-retry behavior for inserts, one test draft per allowlisted blog, and fail-closed uncertainty handling remain in force. Potentially billable credentials, proxy configuration, global terms expiry, quota exhaustion, or 429 still block requests. No other provider's cost policy is changed. To revoke this exception, append an `external.blogger.cost_policy.revoked` audit event; never edit the approval event.
