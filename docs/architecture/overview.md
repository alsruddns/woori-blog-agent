# Phase 1 architecture

Next.js server components and a local configuration UI -> loopback FastAPI with bearer authentication -> PostgreSQL 16. Dashboard mutation routes keep the token on the server, require JSON, restrict the Host to localhost/127.0.0.1:3000 and require an exactly matching Origin. Local OS users are trusted administrators; external deployment requires separate authentication and TLS.

Python worker polls durable job_runs with SKIP LOCKED claiming, lease recovery and bounded attempts. It remains a diagnostic worker; it never consumes publishing_jobs or calls Blogger/AI. Waiting jobs survive reboot and expired leases recover on the next tick.

Languages, country profiles, capabilities, blogs and publishing policies are DB records. The dashboard and API derive lists dynamically. A language can have multiple blogs. A content group can have N language/country localizations with independently numbered immutable versions. Source versions must belong to the same group. See [data model](data-model.md).

Initial registered addresses are https://trend-ko.blogspot.com (ko), https://trend-journal-en.blogspot.com (en), https://trend-zh.blogspot.com (zh-CN) and https://trend-ja.blogspot.com (ja). These are user-provided configuration records; no live request was made to verify them. Google Blog IDs remain NULL. Registration is restricted to canonical HTTPS blogspot.com roots in Phase 1; custom Blogger domains require a later reviewed extension.

Configuration management covers registration/activation, display names, blog addresses, country-specific generation/localization/search-intent/SEO policies, cron schedules with IANA timezones, category names and glossaries. Per-language/country search metrics have storage and a read-only aggregate view, but no Search Console importer yet. Identity fields are immutable to protect history; create a replacement record and deactivate the old one instead of recoding history.

Six readiness states are reported per country profile/blog: generation, translation, quality validation, Blogger connection, test publication and automatic publication. Capability flags alone are insufficient: an exact BCP 47 match in a verified adapter registry is required. Current registries are empty and all AI/publishing network adapters raise before any network access. Automated publication is additionally false at the DB policy constraint and API boundary. There is no flag or setting UI that unlocks it.

Future publishing worker selection must join active languages, blogs and matching country profiles/policies, verify all capabilities, connection/test evidence and explicit operational approval, then apply schedule/quality gates. New language configuration must not require language-specific branches. A supported adapter may accept more tags through capability registration; an unsupported language remains blocked. A durable outbox, per-blog/version idempotency key and remote reconciliation are required before actual publishing retries.

Future pipeline: keyword discovery -> research -> fact/source verification -> generation -> intent-aware localization -> per-version quality/SEO gates -> approval -> Blogger -> Search Console -> improvements. Topics include finance, stocks, crypto, K-pop idols, K-Beauty, Korean travel and restaurants. Country profiles keep intent, terminology and sources independent from translation lineage.

No local model, paid provider, OAuth connector, actual SEO checker, publication scheduler or content comparison UI is claimed implemented. The Google [getByUrl method](https://developers.google.com/blogger/docs/3.0/reference/blogs/getByUrl) is the documented future Blog ID discovery path. The [Posts resource](https://developers.google.com/blogger/docs/3.0/reference/posts) does not list a dedicated hreflang field; actual theme/head support and rendered reciprocal links must be verified separately before claiming hreflang support. No theme was modified.
